## Context

`sharpen-weak-digest-cases` (archived `2026-11-10-sharpen-weak-digest-cases`, capabilities now in `openspec/specs/`) shipped through PR #5 and #6. This change is a delta over those capabilities: it modifies two requirements whose text allowed a wrong result and adds four small requirements. Seams are unchanged: the CLI through `main()` over real `node --test` runs in a temp copy of `tests/fixtures/node-cart/` (`tests/helpers/node-cart.ts`), `formatEnvelope` (envelope seam) and `jsTestAdapter.parse` (adapter seam). Constraints are those of the archived change: INV-1 160 bytes, INV-2 600 EstimatedTokens / 2,400 bytes, INV-3 exit codes, INV-5 gate verdicts, `--format=json` untouched, runtime dependencies `zod` only.

## Decisions

- **Reserve the footer line, fix the blocks first, then list.** v0.1.2 chose its full blocks with a budget that had no listing. The shipped rule counted every listed line while choosing blocks (`fits(kept, all - kept)`), which collapsed 5 blocks to 1 with 25 omitted clusters. New order: (1) blocks: the largest `kept` (at least 1) for which header + blocks + the `+N more clusters (see log)` line fit; (2) listing: as many whole lines as fit in the rest; (3) the unlisted clusters stay in `N`. The `+N` line is reserved before the blocks because the archived requirement says it ends the body at levels 1 to 4. (Alternative rejected: keep the shipped order and raise the cap on listed lines; it still takes blocks away from the clusters the user asked for with `--max-clusters`.)
- **One byte limit.** The shipped code decided with `ceil(bytes/4) <= 600` (up to 2,400 bytes) and cut at 2,399, so an exactly-full listing lost its last bytes to a cut. The digest including its final newline is at most 2,400 bytes: the size decision uses 2,399 bytes before the newline, the same as the cut.
- **One attribution rule: the crash block directly above the entry.** Node prints what a crashed file's subprocess wrote to stderr as one block directly above that file's own entry (TAP: the `# ` comment run above its `# Subtest:`; spec: the lines between the previous tree row and its `✖` row): a location-only line, source and caret, the error, the stack, the trailer `Node.js v<version>`. The adapter takes the last trailer above the entry, the last location-only line before it, and the first `<Name>Error:` line between them; nothing outside the block takes part. This replaces the earlier rules (the first error line of the run, the last line naming the file, the path-block and lone-crash fallbacks), each of which let some other output stand in for the file's error: a setup log (`Error: config.json not found`), the log of a passing file, an error that names a sibling module (`imported from .../helper.js`). It also makes the block rule one function over reporter-specific windows. Measured on Node 22.23.4: missing module, transitive missing module, missing export, syntax error, `ReferenceError`, `throw 42`, `EACCES` and CJS `require` all print this block; `process.exit(1)` prints none (message stays `test failed`, INVALID_RED). Limit: a crashed file whose tests ran and failed on a late error has no crash block; it takes node's `generated asynchronous activity after the test ended` diagnostic above its entry instead. The rule reads where node relays the subprocess's stderr (node's stdout on 22.23.4); a wrapper that captures stderr elsewhere loses the block and degrades to `test failed`/INVALID_RED, the safe verdict for a startup crash. (Earlier alternatives rejected here: path mentions, the nearest error line, a lone-crash fallback; all were shown wrong by real runs.)
- **Read failures of the test file are invalid red.** `Error: EACCES` or `EPERM` containing the test file's quoted absolute path as the error of a crashed file mean node could not read the test file at all: INV-5's runner startup crash. `ENOENT` is not included: node reports a missing file before any subprocess exists (`Could not find ...`), already `INVALID_RED`.
- **Nameless errors with a stack are `Error`.** A TAP block of failure type `testCodeFailure` or `hookFailed` with a `stack:` key and no `name:` key is a plain `Error` (measured: `throw new Error("z")` prints `error: 'z'` and no `name:`; `TypeError` and `AssertionError` print `name:`). The spec reporter prints `Error: z`. A thrown string or number and a failed `t.plan` have no `stack:` key either and keep their text (measured), so the prefix needs `stack:` present.

## Defaults chosen

- A crashed file whose own error is a runtime error other than a missing export (`throw new TypeError(...)` at load) stays `VALID_RED`/`RUNTIME_EXCEPTION`: INV-5 lists `is not a function` among behavioural evidence, and a top-level call to a function that does not exist yet is a legitimate red. Only read failures and files with no attributable error are invalid red.
- Backslash handling covers `\\` only; other TAP escapes stay as they are.
- Cosmetic parity gaps (TAP `diff:` row for nested arrays, spec diff `{ a: 2 }` vs TAP `"a: 2"`) are not changed: the `cluster_id` does not depend on the diff.

## Test seams

- CLI (`main()` over a temp cart copy): every node scenario, the 30-cluster envelope scenario is at the envelope seam.
- Envelope (`formatEnvelope`): the three omitted-cluster scenarios added here.
- `tests/envelope.spec.ts` and `tests/size-and-omission.spec.ts` carry byte limits that move from 2,400 to "2,399 + newline"; they are updated by the task that changes the limit.

## Risks / Trade-offs

- Scenario numbers that the old rule fixed (for instance the 12 listed lines of "When the listing itself does not fit, the tail is only counted") depend on the single byte limit; the task re-measures them and the scenario text is corrected in the same commit if one moves by a line.
- The spec-reporter position rule reads the layout of Node 22.23.4's reporter. Other node versions were not tested.
- Treating `EACCES`/`EPERM` as a startup crash is limited to errors whose text contains the test file's absolute path in single quotes (`open '/dir/file.test.js'`; a sibling `file.test.json` does not match); an `EACCES` on any other file at load (a fixture, a config) stays a behavioural red. `EISDIR` is not included: node reports a directory given as a test path as `Cannot find module`, so it could only match errors of user code.
